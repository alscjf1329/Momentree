# 스크럼 진행

1. **고르기**: `project = MOM AND status = "할 일"`을 조회한다(cloudId `e9aaf6b1-886b-4cd6-834d-9b9fb5fafa66`). 사용자 결정·서버 작업이 필요한 티켓은 건너뛴다. 구현 가능한 게 없으면 결정이 필요한 안건을 제안하고 멈춘다.
2. **시작**: 고른 티켓을 진행 중(전환 ID 21)으로 옮긴다. 평소 대화에서 나온 새 요청은 먼저 티켓으로 만든다.
3. **구현**: Agent 도구로 `isolation: "worktree"` 서브에이전트를 띄운다. 프롬프트에 반드시 넣는다.
   - 티켓 목표와 확정된 결정(추측으로 채우지 말 것)
   - 먼저 읽을 파일, 재사용할 기존 헬퍼
   - 테스트 추가와 `npm test`, `npx tsc --noEmit` 통과 필수
   - 커밋 1개, 메시지 `type(scope): 요약 (MOM-N)`, 마지막 줄 Co-Authored-By
   - push 금지, 끝나면 변경 파일·동작·**검증하지 못한 부분**을 솔직히 보고
4. **보고**: 에이전트 보고를 그대로 믿지 말고 요약해 전달한다(동작, 주의점, 확인 못 한 것, 사용자가 해야 할 일). 마지막에 "머지하고 푸시할까요?"를 묻는다.
5. 승인 전에는 머지·푸시·티켓 검토 중 전환을 하지 않는다. 승인 후는 `ship` 스킬.
