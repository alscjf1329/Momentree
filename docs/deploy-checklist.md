# 배포 체크리스트

운영 서버(`/app/Momentree`)에서 위에서부터 순서대로 진행합니다.

## 배포 전
1. `bin/backup.sh` — 백업 파일이 만들어졌는지 확인합니다.
2. `git pull` 후 `node bin/predeploy-check.mjs .env` — DB는 읽기 전용으로만 열며 아무것도 바꾸지 않습니다. `DATA_DIR`이 `.env`와 다르면 환경변수로 같이 넘깁니다.
3. 결과를 판단합니다.
   - `[차단]`이 있으면(종료 코드 1) 배포하지 않고 해결합니다.
   - 스키마 버전이 낮으면 배포 시 마이그레이션이 자동으로 돌아갑니다. 1번 백업이 최신인지 확인합니다.
   - 즉시 무료로 강등되는 고객, 안내 없이 삭제될 하객 데이터가 있으면 먼저 고객에게 알릴지 정합니다.
   - 예시 슬러그 테스트 데이터는 출력된 SQL로 정리합니다.
   - `NEXT_PUBLIC_*`는 빌드 시점에 고정되므로 `.env`를 바꾼 뒤에는 다시 빌드해야 반영됩니다.

## 배포
4. `bin/deploy.sh` — 끝에서 `/api/health`를 확인합니다. 실패하면 `docker compose logs`를 봅니다.

## 배포 후
- 랜딩, FAQ, 로그인(메일로 코드 수신), 청첩장 보기, 예시 청첩장이 열리는지 확인합니다.
- 예시 청첩장에서 방명록·참석 응답이 저장되지 않는지 확인합니다.
- 텔레그램 테스트 알림: 로그인 후 "문의하기"로 한 건 보내 봅니다(설정이 없으면 문의 접수 불가 안내가 뜹니다).
- 메일 발송: 본인 계정으로 로그인 코드를 받아 봅니다.
- crontab에 `bin/backup.sh`가 등록돼 있는지 확인합니다(`crontab -l`, 방법은 `bin/backup.sh` 상단 참고).
- 프록시가 `x-forwarded-for`를 넘기는지 확인합니다. 아니면 문의하기 rate limit이 모든 사용자를 한 사람으로 봅니다.

## 롤백
이전 커밋으로 `git checkout` 후 `bin/deploy.sh`로 코드를 되돌립니다. 마이그레이션이 돌았다면 코드만 되돌려서는 부족하므로, 컨테이너를 멈추고(`docker compose down`) 1번 백업(`momentree-*.tar.gz`)을 `DATA_DIR`에 풀어 DB를 복원한 뒤 다시 띄웁니다. 복원하면 백업 이후의 데이터는 사라집니다.
